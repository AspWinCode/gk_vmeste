# ВМЕСТЕ AI — карта реализации проекта

Источники требований: `Лист ролей.xlsx` (анкета по 9 ассистентам + уточнения на Листе 2) и уже собранный HTML-фронтенд (`project/frontend`, 8 экранов).

Выбранный стек: **Node.js + TypeScript**, Express, PostgreSQL + Prisma, Redis + BullMQ (очереди для долгих задач: транскрибация, генерация контента), Claude API (Anthropic SDK) как ядро всех ассистентов. Развёртывание — Docker Compose (Postgres + Redis + API), можно поднять как на локальном сервере ГК (для доступа к 1С/эксель), так и в облаке — конфигурация одинаковая, отличаются только `.env` и сетевые доступы.

## 2. Архитектура

```
frontend (уже готов, статический HTML/CSS/JS)
        │  fetch() → REST API (JSON, JWT в заголовке)
        ▼
backend/  Node.js + TypeScript + Express
  ├─ routes/          — HTTP-слой (auth, assistants, transcriber, projects, ksg, finance, land, support)
  ├─ services/         — бизнес-логика и интеграция с Claude API
  ├─ jobs/ (BullMQ)     — асинхронные задачи: STT-транскрибация, генерация саммари, email-рассылка
  ├─ prisma/schema.prisma — модель данных, миграции
  └─ middleware/        — auth (JWT), RBAC по ролям, загрузка файлов (multer)

PostgreSQL — основное хранилище (пользователи, проекты, задачи, версии финмоделей, КСГ-этапы, транскрипции)
Redis      — очередь фоновых задач + кэш
S3-совместимое хранилище (или локальный диск на старте) — аудиофайлы, экспортные .docx/.xlsx
Claude API — суммаризация, извлечение поручений, финмодели-объяснения, генерация текстов СММ
Внешние STT — распознавание речи (Whisper API / Yandex SpeechKit — уточнить у ГК приоритет по рус. языку и диаризации)
```

## 3. Модель данных (ядро, Prisma)

- `User` — сотрудник ГК (email, роль, пароль-хэш)
- `Role` — руководитель / аналитик / офис проекта / оператор ассистента
- `Assistant` — карточка ассистента из каталога (соответствует 9 ролям анкеты + статус: активен/настройка/новый)
- `Project` — площадка/проект ГК (Северный кластер, Участок B-12 и т.д.), общая сущность, к которой привязываются КСГ, финмодели, транскрипции, объекты земли
- `Task` (поручение) — извлекается транскрибатором или создаётся вручную; поля: заголовок, ответственный, срок, статус, источник (meeting_id / manual)
- `TranscriptionJob` — аудиофайл, статус обработки, спикеры, текст, саммари, экспортированные файлы
- `KsgStage` — этап КСГ проекта: план/факт/отклонение/тип (РНВ, финансирование, стройка, продажи)
- `FinanceScenario` — версия финмодели проекта: входные ТЭПы + расчётные метрики (IRR, NPV и т.д.)
- `LandObject` — карточка земельного участка/объекта из мониторинга
- `SupportProgram` — мера поддержки/льгота с параметрами применимости
- `AuditLog` — кто, что и когда сделал (нужно для управленческого доверия к ИИ-агентам)

## 4. Транскрибатор-референт — детальный флоу (P0, реализуется сейчас)

1. `POST /api/transcriber/jobs` — загрузка аудиофайла (multipart), метаданные: проект, тип встречи, участники (email-адреса), язык.
2. Job уходит в очередь BullMQ → воркер:
   a. STT с диаризацией спикеров (внешний провайдер, интерфейс абстрагирован — `SpeechToTextProvider`);
   b. Текст расшифровки передаётся в Claude API с промптом, учитывающим контекст ГК (три направления бизнеса) → получаем: саммари, ключевые тезисы, список поручений (JSON: заголовок/ответственный/срок), протокол.
3. Результат сохраняется в `TranscriptionJob` + создаются записи `Task`.
4. `POST /api/transcriber/jobs/:id/export` — генерация .docx протокола, `POST /:id/send` — email-рассылка участникам (SMTP, база контактов участников встречи).
5. Статусы видны в очереди обработки на фронтенд-странице `transcriber.html` (заменяем демо-данные на реальные fetch-запросы).

## 5. Фазы

- **Фаза 0 ✅:** backend-каркас — auth, роли, Prisma-схема всех сущностей, REST для каталога ассистентов, Docker Compose, подключение фронтенда к API (`login.html`, `auth.js`, `config.js`).
- **Фаза 1 ✅:** Транскрибатор-референт полностью (загрузка → STT → Claude-саммари → поручения → экспорт/email), Task-модуль как общий для всех ассистентов.
- **Фаза 2 ✅:** Финансовый аналитик (`financeCalc.ts` — IRR/NPV методом Ньютона по помесячному CF, риск-комментарий Claude по запросу) и Контроль КСГ (сводный дашборд, CRUD этапов с авторасчётом отклонения, импорт из Excel через `exceljs`).
- **Фаза 3 ✅:** Поиск участков и Мониторинг льгот реализованы БЕЗ автономного скрапинга (обхода антибот-защиты сайтов). Исследовал реальные варианты по каждой площадке:
  - **Циан API / Авито API** — существуют, официальные, бесплатные, но дают доступ ТОЛЬКО к собственным объявлениям агентства/партнёра (загрузка через XML, работа со своими лотами в CRM). Купить или получить доступ к поиску **чужих** объявлений через официальный API нельзя ни за какие деньги — такого продукта у них просто нет. Единственный способ автоматически собирать чужие объявления — скрапинг их страниц поиска в обход защиты, чего я делать не буду. Поэтому по Циан/Авито остаётся ручной сценарий: вставить ссылку на конкретное объявление или текст → Claude разбирает → человек проверяет.
  - **torgi.gov.ru (госторги)** — оказалось, что тут есть настоящие официальные открытые данные (`torgi.gov.ru/opendata`), обычный GET по документированному URL с фильтрами (`bidKind=2` = аренда/продажа земельных участков, `publishDateFrom/To`). Это не скрапинг. Реализовал `POST /api/land/objects/search-torgi` — бэкенд забирает реальный XML и прогоняет каждый лот через ту же Claude-экстракцию, что и ручной текст (точную схему XML-тегов сайт не отдал при разработке — обрыв соединения при попытке проверить, — поэтому парсер не завязан на конкретные названия полей, а передаёт весь лот как есть в Claude).
  - **ДОМ.РФ / ЕИСЖС (наш.дом.рф)** — тоже официальный REST API с данными о проектах застройщиков (не земельные лоты на продажу, а рыночная аналитика по конкурентам/регионам) — не реализован, но задокументирован как легальный источник на будущее.
  - Тот же ручной паттерн для мер поддержки (`src/services/extraction.ts`).
  - **Важно:** сама эта разработческая песочница не имеет прямого выхода в интернет (`fetch()` из Node таймаутится) — эндпоинт `search-torgi` не протестирован живьём здесь, только на компиляции/типах. Первый реальный запуск на вашем сервере — это фактическая проверка, что XML-фид госплощадки действительно отдаёт то, что ожидается.
- **Фаза 4 (почти ✅):** Финмониторинг-дашборд реализован — план из последнего `FinanceScenario`, факт вносится вручную/из Excel как мост до появления REST-выгрузки из 1С ERP Философт. Разборщик почты реализован тем же безопасным паттерном, что «Земля»/«Меры поддержки»: без прямого IMAP-доступа к ящику — письмо вставляется вручную, Claude определяет приоритет/категорию/поручения. Единственное, что осталось нереализованным: **СММ-ассистенты** (нужны ключи Telegram Bot API/Instagram Graph API и подписка на синтез голоса) — заблокированы отсутствием внешних доступов, а не техническим решением.

**Статус: все 9 экранов фронтенда работают на реальных данных бэкенда.** Каталог ассистентов, рабочий стол, транскрибатор, финансовый аналитик, КСГ, земля/объекты, меры поддержки, финмониторинг, разборщик почты — везде реальные запросы к API, а не статичная вёрстка.

- Доступы к Telegram/Instagram API и лицензия на синтез голоса для рилсов.
