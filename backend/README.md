# ВМЕСТЕ AI — backend (MVP: каркас + транскрибатор-референт)

См. общую карту проекта: [../IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md)

## Стек

Node.js + TypeScript, Express, PostgreSQL (Prisma ORM), Redis + BullMQ (очередь фоновых задач), Claude API (Anthropic SDK).

## Запуск локально

```bash
cd backend
cp .env.example .env        # заполнить ANTHROPIC_API_KEY и при необходимости SMTP
npm install

docker compose up -d        # поднимает Postgres + Redis

npm run prisma:migrate      # создаёт таблицы по schema.prisma
npm run prisma:seed         # наполняет каталог ассистентов из анкеты

npm run dev                 # HTTP API на http://localhost:4000
npm run worker              # отдельный процесс — обработка очереди транскрибации (запускать параллельно)
```

## Проверка

```bash
curl http://localhost:4000/api/health
# {"status":"ok"}

curl -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"exec@vmeste.local","password":"password123","name":"Руководитель"}'
# вернёт { token, user } — token подставлять в заголовок Authorization: Bearer <token>

curl http://localhost:4000/api/assistants -H "Authorization: Bearer <token>"
```

Загрузка аудио в транскрибатор (multipart):

```bash
curl -X POST http://localhost:4000/api/transcriber/jobs \
  -H "Authorization: Bearer <token>" \
  -F "audio=@meeting.mp3" \
  -F "meetingType=Совещание" \
  -F "participantEmails=ivanov@vmeste.local,petrov@vmeste.local"
```

Дальше воркер (`npm run worker`) забирает задачу из очереди, прогоняет через STT (пока заглушка — см. `src/services/speechToText.ts`) и Claude API (`src/services/claude.ts`), сохраняет саммари и создаёт поручения (`Task`). Прогресс/результат — `GET /api/transcriber/jobs/:id`.

## Что уже реализовано (Фаза 0–1 из карты)

- Auth (регистрация/логин, JWT), роли пользователей.
- Каталог ассистентов (`/api/assistants`) — наполнен из `Лист ролей.xlsx`.
- Проекты и поручения (`/api/projects`, `/api/tasks`) — сквозные сущности для остальных модулей.
- Транскрибатор-референт целиком: загрузка → очередь → STT (заглушка, готова к подключению провайдера) → Claude-анализ (саммари + структурированные поручения) → экспорт `.docx` → email-рассылка участникам.
- **Финансовый аналитик** (`/api/finance/scenarios`): расчёт ТЭПов и IRR/NPV формулами на бэкенде (`src/services/financeCalc.ts` — метод Ньютона по помесячному CF, допущения по эскроу-раскрытию описаны в комментарии к файлу), сравнение сценариев по проекту, риск-комментарий от Claude по запросу (`/ai-review`).
- **Контроль КСГ** (`/api/ksg/stages`, `/api/ksg/summary`, `/api/ksg/import`): CRUD этапов с авторасчётом отклонения/статуса при простановке факта, сводный дашборд по всем проектам, импорт из `.xlsx` (колонки: Проект, Тип этапа, Этап, План, Факт).
- **Поиск участков** (`/api/land/objects`, `/objects/analyze`) и **Мониторинг льгот** (`/api/support/programs`, `/programs/analyze`): без автообхода сайтов (см. `src/services/extraction.ts` — почему). Пользователь даёт ссылку на конкретное объявление/документ или текст → сервер разово загружает эту страницу → Claude извлекает поля инструментом (structured tool use) → черновик возвращается на проверку, ничего не сохраняется автоматически.
- **`POST /api/land/objects/search-torgi`** — единственный по-настоящему автоматический источник: официальные открытые данные torgi.gov.ru (не скрапинг, обычный GET по документированному URL). Проверьте на реальном сервере с доступом в интернет — из этой песочницы `fetch()` на torgi.gov.ru таймаутится (сама песочница без выхода в сеть), так что живьём код не тестировался, только типы/компиляция. Циан/Авито официального API для поиска чужих объявлений не существует в принципе (их API — только для управления своими), поэтому там остаётся ручной сценарий через `/objects/analyze`.

## Интеграция с фронтендом — уже подключена

`project/frontend` теперь работает с этим API:

- `login.html` — вход/регистрация, сохраняет JWT в `localStorage`.
- `auth.js` — на каждой защищённой странице проверяет токен (редирект на `login.html`, если его нет), даёт `Auth.apiFetch(...)` для запросов с автоподстановкой `Authorization`.
- `config.js` — `window.API_BASE` (по умолчанию `http://localhost:4000/api`; при деплое за общим прокси можно поставить `/api`).
- `transcriber.html` + `transcriber.js` — загрузка файла, очередь с поллингом, саммари/расшифровка/поручения, «Скачать .docx» и «Отправить участникам».
- `finance.html` + `finance.js` — выбор/создание проекта, форма ТЭПов → `POST /finance/scenarios`, таблица сравнения сценариев, риск-комментарий по кнопке (`/ai-review`), история версий по проекту.
- `ksg.html` + `ksg.js` — сводные KPI (`/ksg/summary`), таблица этапов с фильтром по проекту, простановка факта прямо в таблице (пересчитывает отклонение/статус), добавление этапа вручную, импорт `.xlsx`.
- `index.html` + `index.js` — рабочий стол руководителя целиком на реальных данных: критические сигналы (собраны из критичных этапов КСГ + сценариев с низкой маржой), сводка по проектам (последняя финмодель + максимальное отклонение КСГ на проект), лента активности (последние сценарии/расшифровки/обновления КСГ, смёрженные по времени), «Поручения дня» и «Дальше по срокам» из `/api/tasks`.
- `land.html` + `land.js` — вставка ссылки/текста объявления → разбор Claude → проверка → сохранение в подборку; список с фильтром по профилю (Девелопмент/МИРРА), статус меняется кликом по чипу.
- `support.html` + `support.js` — тот же паттерн для мер поддержки: анализ источника → проверка условий → таблица программ с фильтром по региону.
- `finance-monitor.html` + `finance-monitor.js` — план/факт по проектам (план из последней финмодели, факт вносится вручную как мост до 1С), агрегация по направлениям бизнеса, сигналы по отклонениям.
- `assistants.html` + `assistants.js` — каталог из `/api/assistants` с фильтрами по тегам/статусу, карточки со статусом ведут на реализованные модули.
- `mail.html` + `mail.js` — «Разборщик почты»: без прямого IMAP-доступа к ящику (его нет) — вставляете текст письма → Claude определяет приоритет/категорию/поручения → сохраняется в историю, поручения падают в общий `/api/tasks`.

**Все 9 экранов фронтенда работают на реальных данных.** Не реализованы (нужны внешние доступы, которых нет): СММ-ассистенты (Telegram Bot API / Instagram Graph API / синтез голоса) — единственный оставшийся пункт из анкеты.

### Полный запуск для проверки

```bash
# backend
cd backend && docker compose up -d && npm run prisma:migrate && npm run prisma:seed
npm run dev       # окно 1
npm run worker     # окно 2

# frontend — любой статический сервер, напр.:
cd ../frontend && npx serve .   # или python -m http.server 5500
```

Открыть `login.html` → зарегистрироваться → попасть на `index.html` → перейти в «Транскрибатор-референт» → загрузить аудио и наблюдать обработку в реальном времени.
